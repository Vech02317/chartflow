# 任务:通读论文,产出《出图清单》plan.json

## 你的角色
你是论文出图流水线的**第一步**,**只出清单,不出图**。清单要交给人类确认。

## 输入
- 论文全文(用户提供,可能是多个文件或一个 md/docx 转出的文本)
- 项目源码(用户可能只给一部分)

## 输出
- 一个 JSON 文件,保存为 **`plan.json`**,严格符合 `contract/plan.schema.json`
- **只输出这个 JSON 文件的内容**,不要写解释、不要加 markdown 代码块以外的文字

## 工科论文常规图清单(对照用,不是必须全出)

| 章节 | 常规图 | `type` | 抽取依据 |
|---|---|---|---|
| 需求分析 | 用例图 | —— 本期不支持,`skip` | 功能点清单 |
| 概要设计 / 数据库设计 | **实体关系图** | `er` | 建表语句 / models 代码 |
| 数据库设计 | **实体属性图**(每个实体一张) | `attr` | 建表语句 / models 代码 |
| 详细设计 | **类图** | `class` | 类定义 / 接口定义 |
| 详细设计 | **流程图** | `flow` | 正文业务描述段落 |
| 详细设计 | 时序图 | —— 本期不支持,`skip` | 交互描述 |
| 实现 / 测试 | 界面截图 | —— 不支持,`skip` | 真实截图 |

## 规则(必须遵守)
1. **一图一条记录**,`id` 从 `fig1` 顺序编号。
2. `source` 必须**具体**:文件路径,或"第X章 第X节 + 段落关键词"。**禁止**写"全文""相关章节"这类含糊说法。
3. **不编造**论文里没有依据的图。论文需要但本流水线不支持的(界面截图、时序图),仍列为一条,`status` 填 `skip`,`note` 写明原因。
4. `title` 是要印在图上的**图题**,简洁中文,例如"图书借阅管理系统——实体关系图"。
5. 优先安排**源码可支撑**的图(`er`、`attr`、`class`),它们最不容易错;纯靠正文的 `flow` 排后。
6. **`attr` 实体属性图是否要出,取决于论文惯例与导师要求** —— 先看论文正文/往届模板里有没有
   "实体属性图"这一类图。若不需要,整体 `er` 图已经够用,不要硬加。
   若需要,则**每个实体一条记录**,`title` 统一写成"XX实体属性图"(如"读者实体属性图"),
   实体清单以 `er` 图里的实体为准,两张图不许对不上。

## 自检(输出前逐条核对)
- [ ] 文件能被 `python3 -c "import json;json.load(open('plan.json'))"` 解析
- [ ] 每条记录 `type` ∈ {er, attr, class, flow}
- [ ] 每条 `source` 都能指到具体文件或章节

## 完成后
**停下来,请人类确认这份清单**(这是流水线的人工门禁)。确认后再逐图执行 `prompts/extract_<type>.md`。
