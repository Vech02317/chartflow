# 任务:抽出一个实体的属性图数据 attr.json

## 你的角色
产出**一个实体**的陈氏(Chen)属性图数据,严格符合 `contract/attr.schema.json`。
**一张图只画一个实体** —— 论文里有几个实体就出几条记录、几张图,不要把多个实体塞进一张。

## 输入
- 该实体的 models 代码 / 建表语句(**源头真相**)
- 论文正文里对该实体的描述 —— 只作补充;**与源码冲突时以源码为准**

## 图型说明
中央矩形是实体,周围椭圆是属性。属性画成什么样,由 `kind` 决定:

| `kind` | 画法 | 什么时候用 |
|---|---|---|
| `pk` | 椭圆内属性名下**加下划线** | 主键。**必须有且只有一个** |
| `multi` | **双椭圆** | 一个实体可取多个值,如一个读者登记多个"联系电话" |
| `derived` | **虚线椭圆** | 由别的属性算出来、不单独存,如"年龄"由出生日期推算 |
| `normal` | 普通椭圆 | 其余(默认值,不写 `kind` 就是它) |

## 规则(必须遵守)
1. **`label` 用中文属性名**(取 `verbose_name` / 建表注释);**不要**把英文列名画到图上。
   `name` 填英文列名,只用于追溯出处。
2. **`pk` 有且只有一个**。Django 没显式写主键时,主键就是隐含的 `id`,label 取"XX编号"
   (如"读者编号");自建主键照源码写。
3. **不画联系**。外键(`ForeignKey`)和多对多(`ManyToManyField`)**都不画** ——
   它们是**实体之间的联系**,归整体 ER 图管,不属于单实体的属性图。
   `ManyToManyField` 尤其不要当成"多值属性":多值属性指同一个实体自己就能存多个值,而多对多
   指向的是另一个实体,是联系。
   正文或数据字典里若坚持要画,让人来定,不要自己加。
4. **不编造**。源码/建表语句里没有的字段一律不写进 `attributes`;正文里提到、源码里没有的,
   列进"待确认",**不要**先画上。
5. 属性只放**不可再分的数据项**。像"规格"这种还能再拆的,拆成多个属性。
6. 实体中文名取 `Meta.verbose_name`,没有就用类名。

## 输出
只输出 JSON,保存为 `figs/<id>.json`,不要写解释。

## 自检(输出前逐条核对)
- [ ] `attributes` 里有**且只有一个** `kind: "pk"`
- [ ] 每个属性都有中文 `label`
- [ ] 没有把外键 / 多对多字段当成属性画进来
- [ ] 源码里没有的字段,一个都没画

## 完成后
把"待确认"清单回报给人类。属性图最常出的两个错,正是**多画**和**漏画**字段 ——
这张图是给人对着数据库核对的,漏一个字段就等于交了一张假图。
