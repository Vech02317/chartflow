# 任务:从源码抽取实体关系 → `figs/<id>.json`(ER 图)

## 输入(按优先级取其一)
1. 实体类源码(Django / SQLAlchemy / JPA 等)
2. 建表 SQL(DDL)
3. 数据字典文档

## 输出
一个 JSON 文件,保存为 **`figs/<图清单里的 id>.json`**,严格符合 `contract/er.schema.json`。
**只输出 JSON 内容**,不要解释。

## 抽取规则
1. **源码为准,正文只补充**:字段名、类型、外键只从代码或 SQL 取;论文正文与代码冲突时**以代码为准**。
2. `entity.fields` **只放非外键列**(含主键);外键写进 `relation.fk_field`,不要重复成字段。
3. 关系方向:`from` 是**"一"侧**,`to` 是**"多"侧**,`cardinality` 写 `1:N`。
4. `name` 用代码里的原名(如 `BorrowRecord`);`label` 用中文(取 `verbose_name` / SQL comment;没有就意译)。
5. **不编造字段**。有拿不准的字段或关系,**不要写进 JSON**,而是在给人类的回复里单列一条"待确认"。
6. 纯连接表(只有两个外键、无业务字段)——省略成一条 `N:M` 关系,不单列实体。
7. 主键字段带 `"pk": true`(Django 的 `id` 即使没显式声明也算)。

## 模块划分(只在实体多时做)

实体太多时,一张紧凑版会宽到插不进 A4。给实体标上 `module`、顶层写上 `modules`,
引擎就会**自动多产出几张按模块拆的图**(`out/<id>_mod_<模块>.png`),零缩放就能插论文。

**要做**:本图实体数 **≥ 8**。
**不要做**:实体数 **< 8** —— 实测 4 实体紧凑版只有 322×251pt,本来就装得下;硬拆只会让
论文里图数变多、显得零碎。**没有"为了显得完整"而拆的道理。**

### 怎么写
- 顶层 `modules`:每项 `{name, label, title}`。`name` 取源码的 **app 名 / 包名 / 子目录名**
  (只许小写字母数字下划线);`label` 是论文里的中文模块名;`title` 是**要印在图上的图题**,
  如 "书籍模块 E-R 图" —— **自己写完整,不要让脚本去拼**。
- 每个实体加 `module`,取值必须是 `modules` 里出现过的 `name`(写错会被验收拦下)。
- 参考样例:**`samples/campus/figs/fig1.json`**(3 模块 12 实体,照抄它的写法)。

### 模块边界按什么划
- **默认按源码** —— 实体在哪个 app / 包 → 哪个模块。这条可对着源码核,最不容易错。
- **论文正文的功能模块划分与源码不一致时,以论文为准** —— 图要跟论文对得上。
  但**必须**在"待确认"里写明:"源码的 app 划分是 X,本图按论文正文分成 Y"。
- 模块边界拿不准、或论文要求一个实体同时出现在两张模块图里 —— **不要自己编**,回报人类。
  本流水线只支持"一个实体一个模块"的分区。

### 两件必须说清的事
- **不用写外部实体,也不要为外部实体编字段。** 不在本模块的实体会由**引擎**自动画成
  虚线引用框(只写实体名、不列字段)。
- **所以你仍然要把全部实体的字段都写全。** 虚线框不是少写字段的理由 —— 漏字段就是交了一张假图。
  同理,**关系也要写全**:引擎按"关系的 `to` 端(外键所在端)属于哪个模块"把它分给对应那张图,
  保证每条关系都出现在某一张模块图上,一条不丢。

## 自检
- [ ] 每个 `entity.name` 都是源码里真实存在的类名/表名
- [ ] 每条 `relation.from` / `relation.to` 都能在 `entities` 里找到
- [ ] 每个实体有且仅有一个主键
- [ ] 没有把外键列写进 `fields`
- [ ] 实体数 ≥ 8 时写了 `modules`,且**每个实体都标了 `module`**、取值都在 `modules[].name` 里
- [ ] 每个模块至少 1 个实体,没有为凑数而设的模块
- [ ] `module` 与源码的 app/包名对得上(对不上说明理由,写进"待确认")

## 完成后
把"待确认"清单回报给人类(这一步不能省:验收脚本只能证明图和契约一致,证明不了契约和事实一致)。
若做了模块划分,一并说明**模块划分的依据**(源码的哪个 app / 论文的哪一节)。
