# 任务:从论文正文抽取业务流程 → `figs/<id>.json`(流程图)

## 输入
论文正文里**描述业务流程的段落**,通常形如:"用户先……然后系统……若……则……否则……"。

⚠️ 只喂相关那几段,**不要喂全文**——正文抽取是三类图里模糊度最高的,段落越聚焦越准。

## 输出
一个 JSON 文件,保存为 **`figs/<图清单里的 id>.json`**,严格符合 `contract/flow.schema.json`。
**只输出 JSON 内容**,不要解释。

## 抽取规则
1. **节点类型**(`type`):
   - `start` / `end` —— 开始/结束(全图各**只能有一个**)
   - `process` —— 一般操作步骤
   - `decision` —— 判断/分支
   - `io` —— 用户输入或系统输出(如"输入借书证号""显示借阅结果")
   - `subprocess` —— 调用另一个完整流程(如"执行逾期计算流程")
2. **一个动作一个节点**,`label` 用**动宾短语**,如 `"校验借书证"`、`"生成借阅记录"`;**禁止**整句照抄正文。
3. **decision 节点的每条出边必须带 `label`**(`"是"` / `"否"`,或具体条件如 `"库存>0"`)。
4. **单入口单出口**:多个结束点要合并到一个 `end` 节点。
5. 正文没写清的步骤**不要臆造**;若流程明显缺环(如"判断通过"却没有不通过的分支),
   照实产出并写进 `figs/<id>.待确认.md`。
6. `direction` 默认 `TB`(自上而下);步骤超过 12 个或横向分支多时用 `LR`。

## 自检
- [ ] 恰好一个 `start`、一个 `end`
- [ ] 每个 `decision` 的出边都带 `label`
- [ ] 所有 `edges.from` / `edges.to` 都能在 `nodes` 里找到 `id`
- [ ] 没有孤立节点(除单节点图外,每个节点至少有一条入边或出边)

## 完成后(不能省)

**把"待确认"清单写进 `figs/<id>.待确认.md`**(`<id>` 是本图 id),再在对话里简述一遍
(缺环、跳跃、正文含糊处、你补的连接词)。流程图是从**散文**抽的,模糊度四个图型里最高,
要人拍板的地方多半最多 —— **尤其不能只留在对话里**。真的没有要人拍板的,**就写"无"**。

`build.py` 会把各图的这份文件汇总成 `out/待确认.md` 交给人类。
